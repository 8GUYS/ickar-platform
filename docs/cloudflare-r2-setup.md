# Cloudflare R2 Setup Guide — ICKAR Platform

> [!IMPORTANT]
> Cloudflare R2 stores **audio files** for ICKAR. Files are **private** — access is via HMAC-signed URLs generated by your Node.js API. Cover images go to Supabase Storage (public) instead.

---

## Free Tier Limits

| Resource | Free Limit |
|----------|-----------|
| Storage | 10 GB / month |
| Class A operations (write, list) | 1,000,000 / month |
| Class B operations (read) | 10,000,000 / month |
| Egress | **Free** (this is R2's big advantage over S3) |

---

## Step 1 — Create a Cloudflare Account

1. Go to [https://dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up).
2. Create a free account with your email.
3. No credit card required for the free tier, but you must add a payment method to use R2 (Cloudflare verifies identity — you won't be charged within free limits).
4. After signup, go to **R2 Object Storage** in the left sidebar.

---

## Step 2 — Create the R2 Bucket

1. Click **Create bucket**.
2. **Bucket name**: `ickar-media`
   - Must be globally unique within your account.
   - Lowercase, hyphens allowed, no underscores.
3. **Location**: Leave as `Automatic` (Cloudflare chooses the closest region).
4. Click **Create bucket**.

> [!NOTE]
> R2 bucket names are scoped to your account, not globally (unlike S3). `ickar-media` is fine even if someone else has a bucket with that name.

---

## Step 3 — Create an R2 API Token

1. Go to **R2 Object Storage** → **Manage R2 API Tokens** (top right).
2. Click **Create API token**.
3. Configure:
   - **Token name**: `ickar-media-token`
   - **Permissions**: `Object Read & Write`
   - **Bucket**: Select `Specific bucket` → choose `ickar-media`
   - **TTL**: `Forever` (or set an expiry date and rotate regularly)
4. Click **Create API Token**.
5. **Copy immediately** — you will not see the Secret Access Key again:
   - `Access Key ID` → `R2_ACCESS_KEY_ID`
   - `Secret Access Key` → `R2_SECRET_ACCESS_KEY`

---

## Step 4 — Get the Account ID

1. In the Cloudflare dashboard, click your account name in the top right OR go to the main dashboard.
2. The **Account ID** is in the right sidebar on the main dashboard page (or in **R2 → Overview**).
3. It looks like: `a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4`
4. Store as `R2_ACCOUNT_ID`.

Your R2 endpoint URL will be:
```
https://{R2_ACCOUNT_ID}.r2.cloudflarestorage.com
```

---

## Step 5 — Set the Bucket Name Env Var

```
R2_BUCKET_NAME=ickar-media
```

## Step 6 — Set the CORS Policy

CORS must be configured so browsers can interact with R2 (for direct uploads if used, or preflight requests).

1. Go to **R2** → `ickar-media` bucket → **Settings** → **CORS Policy**.
2. Click **Add CORS rule** and paste:

```json
[
  {
    "AllowedOrigins": [
      "https://ickar.vercel.app",
      "https://ickar.ng",
      "https://www.ickar.ng",
      "http://localhost:5173"
    ],
    "AllowedMethods": ["GET", "HEAD", "PUT"],
    "AllowedHeaders": ["*"],
    "MaxAgeSeconds": 3600
  }
]
```

3. Click **Save**.

> [!NOTE]
> Since audio streams via signed URLs from your API (not direct browser-to-R2), CORS mainly matters for `HEAD` requests (duration checks) and potential direct uploads. The signed URL itself bypasses CORS for GET.

## Step 7 — Custom Domain `media.ickar.ng` (Optional for MVP)

This routes `https://media.ickar.ng/{key}` to your R2 bucket, giving you a branded CDN URL instead of the ugly R2 endpoint.

**Prerequisites**: Your domain must be on Cloudflare DNS (see `docs/domain-setup.md`).

1. Go to **R2** → `ickar-media` → **Settings** → **Custom Domains**.
2. Click **Connect Domain**.
3. Enter `media.ickar.ng`.
4. Cloudflare automatically creates the DNS CNAME record.
5. Wait for propagation (~1 minute since you're on Cloudflare DNS).

> [!TIP]
> Skip this for MVP. Your signed URLs use the internal R2 endpoint directly, so users never see the URL. Add the custom domain when you want vanity URLs for public assets.

## Step 8 — How HMAC Signing Works in ICKAR

Your `packages/api/src/routes/streaming.routes.js` already implements HMAC URL signing. Here's how it works end-to-end:

### Flow

```
Mobile/Web App
     │
     ▼
GET /api/stream/{trackId}        ← authenticated request (JWT)
     │
     ▼
streaming.routes.js
  1. Verify JWT → get userId
  2. Check entitlement (subscription or purchase)
  3. Generate signed R2 URL (15-min expiry)
  4. Return { streamUrl, expiresAt }
     │
     ▼
Client fetches audio directly from R2 signed URL
     │
     ▼
Cloudflare R2 validates HMAC signature + expiry
```

### Signed URL Structure

```
https://{ACCOUNT_ID}.r2.cloudflarestorage.com/ickar-media/audio/{trackId}.mp3
  ?X-Amz-Algorithm=AWS4-HMAC-SHA256
  &X-Amz-Credential=...
  &X-Amz-Date=...
  &X-Amz-Expires=900          ← 15 minutes
  &X-Amz-SignedHeaders=host
  &X-Amz-Signature=...        ← HMAC-SHA256 of the canonical request
```

### Environment Variables Required

```env
R2_ACCOUNT_ID=a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4
R2_ACCESS_KEY_ID=your_access_key_id
R2_SECRET_ACCESS_KEY=your_secret_access_key
R2_BUCKET_NAME=ickar-media
```

### File Key Convention

```
audio/{trackId}.mp3        ← track audio files
audio/{trackId}_hq.mp3     ← high quality version (future)
```

## Step 9 — Upload Audio Files

Use the AWS S3-compatible API (R2 is S3-compatible). From your API:

```javascript
import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';

const r2 = new S3Client({
  region: 'auto',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: process.env.R2_ACCESS_KEY_ID,
    secretAccessKey: process.env.R2_SECRET_ACCESS_KEY,
  },
});

await r2.send(new PutObjectCommand({
  Bucket: process.env.R2_BUCKET_NAME,
  Key: `audio/${trackId}.mp3`,
  Body: audioBuffer,
  ContentType: 'audio/mpeg',
}));
```
